# FX팀 업무 워크플로우

## 업무 5단계

프로젝트 하나의 생명주기는 5단계로 구성됩니다. 핵심 3단계(기획/작업/최종) + 선택 2단계(자료조사/QA).

```flow
기획 -> 자료조사? -> 작업 -> QA? -> 최종
```

## 제목 규칙

**형식**: `FX [플랫폼] 프로젝트명 [단계] 내용`

| 구성 요소 | 설명 | 예시 |
|----------|------|------|
| FX | 팀 접두사 (고정) | FX |
| [플랫폼] | 대상 앱/서비스 | [클래식], [PC포커], [공통] |
| 프로젝트명 | 기획 단위 프로젝트 | 무료 충전소(오퍼월) |
| [단계] | 업무 단계 태그 | [기획], [작업], [최종], [자료조사], [QA] |
| 내용 | 업무 상세 | 작업 리스트, 대기실 아이콘 애니메이션 |

**단계별 제목 예시**:

| 단계 | 제목 |
|------|------|
| 기획 | `FX [클래식] 무료 충전소(오퍼월) [기획] 작업 리스트` |
| 자료조사 | `FX [클래식] 무료 충전소(오퍼월) [자료조사] 레퍼런스 수집` |
| 작업 | `FX [클래식] 무료 충전소(오퍼월) [작업] 대기실 아이콘 애니메이션` |
| QA | `FX [클래식] 무료 충전소(오퍼월) [QA] 검수 대응` |
| 최종 | `FX [클래식] 무료 충전소(오퍼월) [최종] 작업 리스트` |

## 단계별 상세

### 1. 기획 (핵심)

**기획 프로젝트 (월별 업데이트 리스트)**:

| 서비스 | 링크 | 기획팀 | 제목 패턴 |
|--------|------|--------|----------|
| 포커 | https://nhnent.dooray.com/task/3287834850785742288 | 포커게임기획팀 | `[통합] 2026년 N월 업데이트` |
| 바둑 | https://nhnent.dooray.com/task/2261351620489037929 | 보드캐쥬얼기획팀 | `2026.N월 정기점검 업데이트` |

**서비스별 업무명 패턴**:

| 서비스 | 전체 업무명 형식 | 게임프로젝트명 예시 |
|--------|----------------|-------------------|
| 포커 | `[플랫폼] 프로젝트명` | [PC포커], [클래식], [홀덤], [공통] |
| 바둑 | `[게임프로젝트명] N월 업데이트 > 업무타이틀` | [PC바둑오목], [M바둑오목], [PC/M바둑오목], [PC장기], [PC신윷놀이], [PC사천성] |

- 바둑은 업무명에 `N월 업데이트 > ` 접두사가 포함됨 → Teamplay에서 자동 제거 (`syncManager.js`)
- 예: `[PC바둑오목] 3월 업데이트 > 사활 컨텐츠: 오늘의 사활` → planningTitle: `[PC바둑오목] 사활 컨텐츠: 오늘의 사활`

기획팀에서 기획문서를 공유하면, 해당 문서를 기반으로:
1. 각 작업을 Task 단위로 분류하여 표로 작성
2. 업무 스케줄 정리 (일정 파악)
3. 연출 컨셉 결정

**본문 구조**:

| 필드 | 값 |
|------|---|
| 카테고리 | 인게임 |
| 조직 | 포커게임기획팀 |
| 일정 | 26.04.01~26.04.25 |
| 점검월 | 26.04 |
| 위키 | 위키 링크 |
| 기획 | 기획 문서 링크 |

**작업 리스트 표**:

| No | Task | 카테고리 | 일정 | 컨셉 | 비고 |
|----|------|---------|------|------|------|
| 1 | 대기실 아이콘 애니메이션 | 대기실 | 04.01~04.05 | 기존 스타일 유지 | |
| 2 | 인게임 이펙트 교체 | 인게임 | 04.07~04.15 | 신규 컨셉 | 기존 리소스 활용 |
| 3 | 결과창 연출 | 결과 | 04.16~04.22 | 화려한 연출 | 신규 제작 |

**역할**: 프로젝트의 전체 작업 범위를 정의하는 마스터 문서
**핵심 가치**:
- 기획 리뷰 후 작업 범위를 명확히 정의
- Task별 일정과 연출 컨셉을 사전에 결정
- 이후 [작업] 업무 생성의 기반 데이터

---

### 2. 자료조사 (선택)

작업 착수 전 레퍼런스 수집, 기술 검토, 가능성 탐색 등.

---

### 3. 작업 (핵심)

실제 제작/구현을 수행하는 단계. 기획 문서의 각 Task별로 개별 업무가 생성됨.

**본문**: 프로젝트 정보 (카테고리/조직/일정/점검월/위키/기획)
**댓글**: 작업 과정 노트 (날짜별 진행내용 기록 - 팀플레이 Sync 대상)

**역할**: Gantt 차트의 주요 트래킹 단위 (진행률, Work 마크, 보고서)

---

### 4. QA (선택)

QA팀 검수 대응. QA 업무 등록 모듈(QA Register)로 자동 생성 가능.

---

### 5. 최종 (핵심)

작업 결과물을 정리하여 최종 산출물 리스트를 만드는 단계.

**본문 구조**:

| No | Task | 이미지/영상 |
|----|------|------------|
| 1 | 대기실 아이콘 애니메이션 | (스크린샷/동영상 링크) |
| 2 | 인게임 이펙트 교체 | (스크린샷/동영상 링크) |

**역할**: 프로젝트 완료 확인 및 검수 자료, 연출 모음(FX Collection) 데이터 소스

---

## 상태태그 정리

제목의 `[태그]`는 업무의 **종류/단계**를 나타내며, Task Status(Ready/Doing/Done)와는 무관.

| 상태태그 | 단계 | 설명 |
|---------|------|------|
| `[기획]` | 기획 | 기획리뷰 후 작업 리스트 정리 |
| `[작업]` | 작업 | 실제 제작/구현 진행 |
| `[최종]` | 최종 | 산출물 정리 (이미지/영상) |
| `[자료조사]` | 자료조사 | 레퍼런스/기술 검토 |
| `[QA]` | QA | QA팀 검수 대응 |
| `[완료]` | - | 완료 표시 (모든 단계 공통) |
| `[검수]` | - | 검수 진행 중 (레거시) |

## 프로젝트 단위 업무 구조

하나의 프로젝트는 다음과 같은 Dooray 업무 트리를 가짐:

| 업무 | 수량 | 설명 |
|------|------|------|
| **[기획]** 작업 리스트 | 1개 | 마스터 문서 |
| **[작업]** Task A, B, C... | N개 | Gantt 트래킹 단위 |
| **[자료조사]** 레퍼런스 | 0~1개 | 선택 |
| **[QA]** 검수 대응 | 0~1개 | 선택 |
| **[최종]** 작업 리스트 | 1개 | 산출물 정리 |

## 현재 시스템 분석

### 잘 되고 있는 것

| 영역 | 현재 지원 | 비고 |
|------|----------|------|
| [작업] 생성 | Task Creator가 `[작업]` 태그로 자동 생성 | `taskCreator.js` |
| [작업] 트래킹 | Gantt 차트, Work 마크, 진행률, 보고서 | 핵심 기능 |
| [작업] Sync | 댓글 파싱 → Task/Work 자동 반영 | `syncManager.js` |
| [최종] 연출 모음 | FX Collection이 `[최종]` 업무에 댓글/본문 작성 | 그룹 우클릭 |
| [QA] 등록 | QA Register가 FX 업무로 자동 변환 | `qaRegister.js` |
| 위키 생성 | Wiki Panel이 프로젝트별 위키 페이지 자동 생성 | `wikiPanel.js` |
| 제목 파싱 | `[플랫폼]`, `[상태태그]` 분리 파싱 | `commentParser.js` |

### 문제점 및 개선 기회

#### P1. [기획] 단계 미지원

**현재**: [기획] 업무는 수동 생성, Teamplay에서 관리하지 않음
**문제**:
- 기획 → 작업 전환 시 작업 리스트를 수동으로 개별 업무로 분해해야 함
- 기획 리스트와 실제 작업 Task 간 매칭/추적 불가
- 프로젝트 전체 범위 파악이 Dooray에서만 가능

**개선안**: [기획] 업무 생성 자동화
- 기획 업무 생성 시 작업 리스트 표 자동 포함
- [기획] → [작업] 일괄 변환 기능 (표의 각 행을 개별 [작업] 업무로 생성)
- 기획 업무와 작업 업무 간 관계 추적 (parentTaskUrl 등)

---

#### P2. [최종] 단계 수동 생성

**현재**: [최종] 업무는 수동 생성, FX Collection은 기존 [최종] 업무에 쓰기만 함
**문제**:
- [최종] 업무 자체를 먼저 수동으로 만들어야 FX Collection 사용 가능
- [기획]의 작업 리스트와 [최종]의 Task 리스트가 동기화되지 않음

**개선안**: [최종] 업무 자동 생성
- FX Collection 실행 시 [최종] 업무가 없으면 자동 생성
- [기획] 작업 리스트를 템플릿으로 활용

---

#### P3. 단계 간 연결 부재

**현재**: [기획], [작업], [최종]이 같은 프로젝트인지는 제목 패턴으로만 유추
**문제**:
- 프로젝트 전체 진행 상황(기획됨 → 작업중 → 완료)을 한눈에 볼 수 없음
- 기획에 있지만 작업이 안 만들어진 항목 식별 불가

**개선안**: 프로젝트 단위 뷰
- `[플랫폼] 프로젝트` 키로 [기획]/[작업]/[최종] 업무를 그룹핑
- Planning 차트 또는 별도 뷰에서 단계별 진행 상태 표시
- 누락 작업 감지: 기획 리스트에 있지만 [작업] 업무가 없는 항목 알림

---

#### P4. Task Creator가 [작업]만 생성

**현재**: `taskCreator.js`는 `[작업]` 태그를 하드코딩
**문제**: [기획], [최종], [자료조사] 업무는 수동 생성 필요

**개선안**: 단계 선택 옵션 추가
- Task Creator에 "업무 유형" 드롭다운 (기획/작업/최종/자료조사/QA)
- 유형별 본문 템플릿 자동 적용
- [기획] 선택 시: 작업 리스트 표 템플릿 포함
- [최종] 선택 시: 이미지/영상 컬럼 포함 표 템플릿

---

#### P5. Gantt에서 [작업] 외 업무 관리 미흡

**현재**: Gantt는 모든 상태태그 업무를 동일하게 취급
**문제**:
- [기획], [최종] 업무도 Gantt에 등장하지만 진행률 관리가 [작업]과 다름
- [기획]은 리뷰 완료 여부, [최종]은 산출물 첨부 여부가 중요

**개선안**: 상태태그별 시각 구분
- Gantt Task 컬럼에 상태태그 뱃지 표시 (기획=보라, 작업=파랑, 최종=초록 등)
- 필터에 상태태그 추가 (작업만 보기 / 기획만 보기 등)

## 우선순위 제안

| 순위 | 항목 | 효과 | 난이도 |
|------|------|------|--------|
| 1 | P4: Task Creator 유형 선택 | [기획]/[최종] 생성 자동화 | 낮음 |
| 2 | P5: 상태태그 시각 구분 | 업무 종류 한눈에 파악 | 낮음 |
| 3 | P2: [최종] 자동 생성 | FX Collection 워크플로우 개선 | 중간 |

| 5 | P3: 프로젝트 단위 뷰 | 전체 진행 추적 | 높음 |
